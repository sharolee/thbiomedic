# ADR-002：中英文双语架构

- **状态**：提议（Proposed）— 与 ADR-001 同步，**待客户确认**整体技术栈后同步落地
- **日期**：2026-09-30
- **决策者**：架构师老欧
- **相关文档**：`docs/adr/ADR-001-frontend-stack.md`、`docs/architecture.md`、`docs/content-inventory.md`
- **影响范围**：路由、内容数据模型、语言切换组件、SEO、构建验收

---

## 1. 背景

现有站点为**物理分目录**双语：中文站 `https://www.thbiomedic.com/zn/`，英文站根目录 `https://www.thbiomedic.com/`。两套站点 URL 结构完全同构，`lcid`（分类 ID）一一对应（见盘点 §3.2）。中英文内容页标题、正文、面包屑均为对应语言版本。

新版需满足：
- 每页面中英双语，内容一一对应，**无未翻译占位**
- 语言切换 UI 可见、可达、SEO 友好
- 后续内容维护可验证「双语完整性」

---

## 2. 约束

| 约束 | 说明 |
|---|---|
| URL 结构 | 必须可映射到现有 URL（或可 301 重定向），利于 SEO 迁移 |
| 语言前缀 | 推荐 `/zh/`、 `/en/`（符合现状 `/zn/` 与根目录的语义，统一为两字母代码） |
| 内容对应 | 12 个产品详情、17 个二级分类、6 大栏目、首页、关于、资源、联系——逐页一一对应 |
| 空分类处理 | 15/17 二级分类无产品（仅横幅+表单），仍需双语页 |
| 搜索/表单 | 站内搜索、在线留言表单为全站通用，语言无关（仅占位文案随语言） |
| 视频/PDF | 文件名与 URL 无语言区分，需按语言提供对应标题/描述元数据 |
| 构建产物 | 纯静态 HTML，每语言独立目录，便于任意静态托管 |

---

## 3. 方案对比

### 3.1 语言路由策略

| 策略 | 示例 URL | 优势 | 劣势 | 适配性 |
|---|---|---|---|---|
| **目录前缀（推荐）** | `/zh/`, `/zh/products/...`<br>`/en/`, `/en/products/...` | **SEO 标准、可缓存、CDN 友好、hreflang 天然映射、现状同构、静态托管零配置** | 需在每页注入前缀 | ✅ 最佳 |
| 子域名 | `zh.thbiomedic.com` | 彻底隔离 | 证书、CDN、Cookie、SEO 权重分散、运维复杂 | ❌ 过度 |
| 查询参数 | `?lang=zh` | 实现简单 | **SEO 差、不可缓存、无 hreflang、分享链接丢语言** | ❌ 不可用 |
| Cookie/接受语言 | 无 URL 变化 | 用户无感 | **SEO 灾难、不可分享、不可收藏、爬虫仅抓默认语言** | ❌ 禁用 |

> **结论**：**目录前缀 `/zh/`、 `/en/`**。兼容现有结构（`/zn/` → `/zh/` 仅重命名，301 重定向即可）。

### 3.2 内容字典组织

| 组织方式 | 示例 | 优势 | 劣势 | 适配性 |
|---|---|---|---|---|
| **语言无关键 + 单语言字典文件（推荐）** | `content/zh.json`、`content/en.json` 或 `content/{zh,en}/*.md` | **单语言维护、翻译对齐可视化、Git diff 只显示改动语言、构建期可校验键完整性** | 需工具校验键同步 | ✅ 最佳 |
| 嵌套单文件 | `content.json` `{ "zh": {...}, "en": {...} }` | 单文件 | 冲突大、diff 噪声、翻译对齐难、键缺失不易发现 | ❌ |
| Markdown 前置元数据 | 每页 `.md` 内 `lang: zh` | 就近 | 结构页（列表/详情）需大量重复、跨语言对齐依赖文件名约定 | ⚠️ 仅适内容页 |
| CMS/Headless | 外部 API | 非技术人员可编 | 本项目无 CMS、引入外部依赖、静态构建需同步 | ❌ 过度 |

> **结论**：**语言无关键 + 单语言字典文件**。键名基于页面/组件语义（如 `hero.title`、`nav.products`、`product.easy-lock.desc`），每语言一套同键文件。构建期强制校验键集合完全一致。

### 3.3 语言切换 UI

| 位置/形态 | 实现要点 | SEO 影响 |
|---|---|---|
| **页头右侧固定（推荐）** | 图标/文字「中 / EN」，点击跳转对应语言**同路径**页面（如 `/zh/products/easy-lock` ↔ `/en/products/easy-lock`） | 需在每页 `<head>` 注入 `hreflang` 双向链接 |
| 页脚二级 | 兜底入口 | 补充 |
| 自动检测跳转 | 首次访问按 `Accept-Language` 302 到对应语言首页，**不覆盖显式语言选择** | 需配合 `x-default` hreflang |

> **结论**：页头固定切换器 + 首页自动检测 302，**显式选择优先**。切换器链接为对应语言的**同一语义页面**，非单纯跳首页。

### 3.4 SEO 与 hreflang

每页面必须在 `<head>` 输出：
```html
<link rel="alternate" hreflang="zh-CN" href="https://thbiomedic.com/zh/current-path" />
<link rel="alternate" hreflang="en"     href="https://thbiomedic.com/en/current-path" />
<link rel="alternate" hreflang="x-default" href="https://thbiomedic.com/en/current-path" />
```
- `x-default` 指向英文版（国际默认）。
- sitemap.xml 需包含所有语言版本 URL，并在 `<url>` 内嵌 `<xhtml:link rel="alternate" hreflang="..." href="..." />`。

### 3.5 后续校验责任

| 阶段 | 校验项 | 实现方式 | 责任 |
|---|---|---|---|
| **开发期** | 字典键完整性（两语言键集合一致） | 构建脚本 `npm run i18n:check` 失败即报错 | 开发 |
| **开发期** | 页面级 hreflang 双向一致 | 同步生成时自动写入，单元测试覆盖 | 开发 |
| **CI** | 空翻译检测（值为空/同源语言） | 简单脚本扫描字典值 | CI |
| **验收期** | 语言切换器跳转正确性 | Playwright E2E：全站每页点击切换器 → URL 对应、内容语言匹配 | 视觉验收官 |
| **上线后** | 新增页面双语同步 | PR 模板强制要求双语字典；CI 阻断 | 维护者 |

| 维度 | 选择 |
|---|---|
| 路由策略 | **目录前缀**：`/zh/`、`/en/` |

## 5. 详细设计

### 5.1 URL 映射规则（与现状对应）

| 语义 | 中文站（现状） | 英文站（现状） | 新版规范 URL |
|---|---|---|---|
| 首页 | `/zn/index.html` | `/index.aspx` | `/zh/`、`/en/` |
| 关于我们 | `/zn/AboutUs/index.html` | `/AboutUs/index.aspx` | `/zh/about/`、`/en/about/` |
| 产品一级分类 | `/zn/Products/index.aspx?lcid=58` | `/Products/index.aspx?lcid=42` | `/zh/products/`、`/en/products/` |
| 产品二级列表 | `/zn/Products/list.aspx?lcid=62` | `/Products/list.aspx?lcid=46` | `/zh/products/<slug>/`、`/en/products/<slug>/` |
| 产品详情 | `/zn/Products/info.aspx?itemid=239` | `/Products/info.aspx?itemid=224` | `/zh/products/<slug>/<product-slug>/`、`/en/...` |
| 资源-下载 | `/zn/Downloads/list.aspx` | `/Downloads/list.aspx` | `/zh/resources/downloads/`、`/en/...` |
| 资源-视频列表 | `/zn/Videos/list.html` | `/Videos/list.aspx` | `/zh/resources/videos/`、`/en/...` |
| 视频子栏目 | `/zn/Videos/list_lcid_30.html` | `/Videos/list.aspx?lcid=27` | `/zh/resources/videos/<category-slug>/`、`/en/...` |
| 新闻 | `/zn/News/list.html` | `/news/list.aspx` | `/zh/news/`、`/en/news/` |
| 联系我们 | `/zn/ContactUs/index.html` | `/ContactUs/index.aspx` | `/zh/contact/`、`/en/contact/` |

**Slug 规则**：
- 一级分类：英文 slug（如 `low-temp-thermoplastics`、`pet-rehabilitation`）
- 二级分类：英文 slug（如 `easy-lock`、`air-mesh`）
- 产品：英文 slug（如 `ankle-splint`、`hock-thermoplastic`）
- 中文站 URL 仍用英文 slug（避免中文 URL 编码/SEO 问题），语言由前缀区分。

> 与现状 `.aspx?lcd=` 映射在部署层做 301 重定向表，不进入前端构建。

### 5.2 字典键命名规范

```
<页面/组件>.<语义字段>

示例：
nav.home, nav.about, nav.products, nav.resources, nav.news, nav.contact
hero.title, hero.subtitle, hero.cta
about.company_profile, about.history_alt, about.certificates[N].title
products.categories[N].name, products.categories[N].desc
product.title, product.desc, product.specs, product.video_poster
resources.downloads[N].title, resources.downloads[N].file
resources.videos.categories[N].name, resources.videos.items[N].title
news.empty_message
contact.phone, contact.email, contact.address, contact.form.*
footer.icp, footer.wanhu, footer.social.*
form.salutation, form.company, form.email, form.first_name, form.last_name, form.phone, form.message, form.submit
```

- 键名**仅用英文、小写、点分层**，语义化而非结构化。
- 共享组件（导航、页脚、表单、面包屑）键名**全局唯一**，复用字典值。

### 5.3 字典文件结构（建议）

```
src/
├── content/
│   ├── zh/
│   │   ├── common.json        # 导航、页脚、表单、按钮等全站通用
│   │   ├── pages/
│   │   │   ├── home.json
│   │   │   ├── about.json
│   │   │   ├── products-index.json
│   │   │   ├── product-detail.json
│   │   │   ├── resources.json
│   │   │   ├── news.json
│   │   │   └── contact.json
│   │   └── data/
│   │       ├── categories.json      # 10 个一级分类：{ slug, name, desc, children[] }
│   │       ├── products.json        # 12 个产品详情：{ slug, categorySlug, name, desc, images[], video? }
│   │       └── videos.json          # 视频元数据
│   └── en/
│       ├── common.json
│       ├── pages/... (同键)
│       └── data/... (同键，值为英文)
```

> Astro 内容集合可直接按此结构加载并类型校验（见 `docs/architecture.md`）。

### 5.4 语言切换器组件规范

```tsx
// 伪代码：语言切换器逻辑
function LanguageSwitcher({ currentPath, currentLang }) {
  const otherLang = currentLang === 'zh' ? 'en' : 'zh';
  // currentPath 如 /zh/products/easy-lock/ankle-splint/
  // 目标路径 = 替换前缀
  const targetPath = currentPath.replace(`/${currentLang}/`, `/${otherLang}/`);
  return (
    <a href={targetPath} hreflang={otherLang} aria-label={otherLang === 'zh' ? '中文' : 'English'}>
      {otherLang === 'zh' ? '中文' : 'EN'}
    </a>
  );
}
```

- **必须**链接到对应语言的**同一语义页面**，非首页。
- 404 场景：若目标语言该页面不存在（不应发生，因构建期校验），fallback 到对应语言首页。

### 5.5 视频/PDF 等媒体资源的双语元数据

视频与 PDF 文件本身无语言区分（同一文件供双语站复用），但**标题、描述、缩略图 alt**需双语。字典中维护：

```json
// zh/data/videos.json
{ "items": [{ "file": "20211209094814255.mp4", "title": "可调膝关节支具演示", "desc": "...", "poster": "..." }] }

// en/data/videos.json
{ "items": [{ "file": "20211209094814255.mp4", "title": "Adjustable Knee Orthosis Demo", "desc": "...", "poster": "..." }] }
```

## 6. 成本与风险

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| 翻译缺失/不一致导致上线漏译 | 中 | 高 | 构建期强制校验键完整性 + CI 空值扫描 + PR 模板强制双语 |
| 语言切换器指向 404 | 低 | 中 | 构建期生成所有语言同键页面；切换器逻辑单测覆盖 |
| hreflang 缺失/错误导致 SEO 受损 | 低 | 高 | 模板强制注入；单元测试覆盖 head 输出 |
| URL 迁移未 301 导致旧收录失效 | 高 | 高 | 部署层配置完整 301 映射表（旧 `.aspx` → 新静态路径），属运维任务 |
| 团队不熟悉字典维护流程 | 中 | 中 | `docs/architecture.md` 给出「新增页面/修改文案」标准操作步骤 |

## 7. 回滚方式

双语架构为**数据模型层决策**，不绑定具体框架：
- 若回退到方案 A（纯 HTML + Vite），字典文件结构不变，仅改用构建期简单模板引擎（或 11ty）读取字典生成 HTML；路由、键名、校验脚本全复用。
- 产物仍为 `/zh/`、`/en/` 静态目录，部署无变化。

---

## 8. 决策摘要（TL;DR）

- **路由**：`/zh/`、`/en/` 目录前缀（兼容现状、SEO 标准、静态托管零配置）
- **内容**：语言无关键 + 单语言字典文件（`src/content/{zh,en}/**`），构建期强制键一致性校验
- **切换器**：页头固定，同语义页面互链；首页可 `Accept-Language` 302
- **SEO**：全页面 `hreflang` 双向 + `x-default` + 双语 sitemap
- **验收**：构建门禁 + CI 空值检测 + Playwright E2E 切换器全站验收
- **状态**：提议，与 ADR-001 同步待客户确认
