# ADR-005：留言表单提交方案（email 直达指定邮箱）

- **状态**：已接受（Accepted）— 客户 2026-10-09 于 SHAR-51 评论拍板「留言表单用 email 方式发送到指定邮箱」
- **日期**：2026-10-09　｜　**决策者**：客户（方式）+ 架构师老欧（实现选型）
- **相关文档**：`docs/plan/build-plan.md` §3-D7、`docs/content-inventory.md` §4.5（表单字段与联系邮箱盘点）、`PROJECT_STANDARDS.md` §8.7（可访问性底线）

## 1. 背景

静态站无法原生收留言。候选：`mailto:` 直发、第三方表单→邮件服务（Formspree 等）、部署平台 serverless 端点。部署目标未定（build-plan C7），客户要求以 email 方式送达指定邮箱、且不引入付费外部依赖。

## 2. 决策

1. **方案：`mailto:` 结构化邮件**。表单字段（沿用原站 7 字段：称呼/公司*/邮箱*/名*/姓*/手机/内容）经前端校验后拼装主题与正文，提交即唤起用户邮件客户端发往指定邮箱。
2. **收件邮箱**：`thsales@biomedichk.com`（原站联系方式页公开邮箱，中英站同，盘点 §4.5）；在 `src/content/{zh,en}/data/contact.json` 单点维护，可随时人工更换。
3. **提交后 UI**：提示「已为您唤起邮件客户端」+ 备用引导（直接复制邮箱地址）；无 JS 降级为纯 `mailto:` 链接。
4. **预留升级**：若上线后体验不达标（无邮件客户端的用户流失），切换为第三方表单服务或部署平台 serverless 端点——提交动作收敛在单一常量/函数，业务组件零改动；届时属外部可见变更，升级人工确认。

## 3. 备选方案对比（结论级）

| 方案 | 优势 | 劣势 | 结论 |
|---|---|---|---|
| A. `mailto:` 直发 | 零依赖、零成本、平台无关、当天可用 | 依赖用户本机邮件客户端；体验一般 | ✅ 本期采用（客户拍板 email 直达的最简实现） |
| B. 第三方表单服务 | 体验好、送达可靠 | 外部依赖 + 免费额度/付费；需注册账号 | 备选（ADR §2.4 触发时升级） |
| C. serverless 端点 | 完全可控 | 依赖部署平台确定；引入服务端维护面 | 备选（同上） |

## 4. 风险与回滚

- 邮箱为原站已公开地址，无新增暴露面；垃圾邮件风险与原站现状持平。
- 回滚/升级成本：一次提交函数替换，表单 UI 与校验层不动。
